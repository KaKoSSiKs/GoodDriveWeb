## 🔴 КРИТИЧНЫЕ БАГИ

### 1. **Форма онлайн-помощи не отправляет данные на сервер**

**Местоположение:** `src/routes/+page.svelte:145-150`

**Проблема:**
- Форма консультации (`handleConsultationSubmit`) только показывает `alert()`, не отправляет данные на сервер
- Нет API endpoint для сохранения запросов консультации
- Нет модели в базе данных для хранения запросов
- Данные не попадают в админ-панель

**Шаги для воспроизведения:**
1. Перейти на главную страницу
2. Прокрутить до блока "Онлайн-помощь специалиста"
3. Заполнить форму (VIN, имя, телефон)
4. Нажать "Получить консультацию"
5. Появляется только alert, данные никуда не отправляются

**Ожидаемое поведение:**
- Данные отправляются на API endpoint `/api/help-requests`
- Запрос сохраняется в БД как `HelpRequest` с типом `help_request`
- Запись появляется в разделе "Запросы" админ-панели
- Пользователь видит сообщение "Ваша заявка отправлена. Специалист свяжется с вами в ближайшее время."
- Форма очищается после успешной отправки

**Приоритет:** 🔴 **КРИТИЧНЫЙ**

**Приоритет:** 🔴 **КРИТИЧНЫЙ**

## 📝 UX-ПОТОКИ

### 1. Онлайн-помощь (исправленный поток):

1. Пользователь заполняет форму: VIN, имя, телефон, комментарий
2. При отправке валидируется телефон (11-12 цифр)
3. Если валидация не прошла → показывается ошибка
4. Если валидация прошла → данные отправляются на `/api/help-requests`
5. Сервер сохраняет запрос в БД (тип: `help_request`)
6. Пользователь видит сообщение: "Ваша заявка отправлена. Специалист свяжется с вами в ближайшее время."
7. Форма очищается
8. Запрос появляется в админ-панели в разделе "Запросы"
9. Менеджер может обработать запрос и изменить статус

### 2. Поиск по каталогу:

1. Пользователь вводит запрос в поисковую строку
2. Autocomplete показывает предложения (debounce 300ms)
3. Если запрос пустой и пользователь пытается искать → сообщение "Введите номер или название детали"
4. Если результаты найдены → отображаются карточки товаров
5. Если результатов нет → сообщение "Ничего не найдено. Попробуйте изменить запрос."
6. Пользователь может кликнуть на товар или добавить в корзину

### 3. Оформление заказа:

1. Пользователь добавляет товары в корзину
2. Переходит в корзину, проверяет товары
3. Нажимает "Оформить заказ"
4. Заполняет форму: имя, телефон (11-12 цифр), адрес, город, комментарий
5. Валидация всех полей, включая телефон
6. Если валидация не прошла → показываются ошибки
7. Если валидация прошла → заказ создается через `/api/orders`
8. Заказ сохраняется в БД с уникальным ID
9. Корзина очищается
10. Пользователь видит сообщение "Ваш заказ успешно оформлен!"
11. Заказ появляется в админ-панели в разделе "Заказы"
